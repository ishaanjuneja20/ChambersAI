# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-10 | Acts chunked per section; judgments per paragraph | exact citations, focused vectors |
| 2026-10 | Domain tags as soft boost | tags are model-labelled, unverified by a lawyer |
| OPEN | Hosting / vector store | ~900k judgment chunks exceed free tiers; consider int8 or case-level-first retrieval |
| 2026-10 | No OCR-based Hindi chunks yet; Hindi queries retrieve English chunks via multilingual embeddings | OCR drops digits and headings (only ~40-55% of sections alignable); noisy text would hurt retrieval and citations. Revisit if cross-lingual retrieval tests poorly |
| 2026-10 | Embedding model chosen by tools/eval_embeddings.py on the draft test set | picks on measured EN and HI hit@5 and the refusal threshold, not on reputation. Baseline (char TF-IDF): EN hit@5 0.61, HI 0.00 |
| 2026-10 | Embedding model: BAAI/bge-m3 (local, 1024-d) | Draft test set: EN hit@5 .92, HI hit@5 .95 (e5-base .82/.68, e5-small .82/.58, TF-IDF .61/0). Hindi questions find English sections without Hindi chunks. Gemini embeddings and Gemini query rewriting NOT tested (free-tier 429s); optional later |
| 2026-10 | Domain boost 0.02; one hit per section; per-language refusal thresholds EN 0.635, HI 0.589 | measured on the draft test set (traps refused 100% EN / 90% HI, real questions kept 89% / 84%). Thresholds are provisional until a lawyer-reviewed test set exists |
| 2026-10 | Answer text cites sources only by chunk id; citation strings come from chunk metadata; unknown ids are dropped, and no verifiable citation means refuse | CLAUDE.md rules 2-3 |
| 2026-10 | Embed queries on CPU, not Apple MPS | MPS gave wrong query vectors (sim 0.21 vs 0.71 for the same question on CPU); stored document vectors are fine. Re-ran the eval with --device cpu: identical scores, so the eval and thresholds are unaffected (batched queries were fine; the fault only hit single-query encoding) |
| 2026-10 | Query rewriting (Gemini flash-lite) before search; score = better of original and rewritten query | On everyday-wording questions (tests/eval/questions_lay.json) it lifted Hindi hit@1 .40 -> .73 and hit@5 .73 -> .93, English hit@1 .53 -> .67; easy set also improved (EN hit@1 .74 -> .79, HI .68 -> .76). Costs one extra cheap Gemini call per question; falls back to the original question if the call fails |
| 2026-10 | Refusal thresholds EN 0.64, HI 0.60 (replaces .635 / .589) | Pooled both test sets with rewriting on: EN keeps 92% / refuses 93% of traps, HI keeps 96% / refuses 86%. Tilted to answering because the Gemini "no source" instruction and the citation check are second guards. 14 traps per language is a small sample: re-tune with a lawyer-reviewed set |
| 2026-10 | Judgments: two-stage retrieval. Stage 1 = one embedded "case card" per Supreme Court judgment (case name + citation + the opening of the text, which is the headnote for reported cases); stage 2 = search the paragraphs of the top cases (not built yet) | Embedding every paragraph (~900k chunks, ~25 h on the Mac, ~3.7 GB) is too slow and too big for free hosting; 38,366 cards are ~160 MB and ~1 h. Citation fields (case name, SCR citation, year, court) come from judgments_metadata_all.csv, never from generated text |
| 2026-10 | Embed all 38,366 judgments, no smaller subset first | Cards are cheap; a subset would only hide recall problems. Domain tags stay a soft boost |
| 2026-10 | Licence: the judgments are the AWS Open Data "Indian Supreme Court Judgments" set (Dattam Labs), CC-BY-4.0 | Attribution required in the app and README: see README.md in the data folder |
| 2026-10 | Judgments: also embed every paragraph chunk (tools/build_judgment_chunks.py), ~1,400-char chunks, float16 | Team decision to embed full text rather than rely only on case cards. Measured on sample years: ~38 chunks per judgment, so ~1.45M chunks (~360M tokens) for all 38,366 judgments, ~3 GB of float16 vectors. Mac Air speed is not measured yet: benchmark one year first; GPU (Colab/Kaggle) or a domain-scoped subset (22,169 judgments have one of our 6 domains) are the fallbacks |
| 2026-10 | Judgment scripts keep one copy per case path | corpus/judgments has 43,546 records but 38,366 unique paths: extract_judgments.py wrote 5,180 cases twice (5,177 identical text, 3 differ by a character). Without dedupe, chunk and card ids would repeat and ~12% of embedding time would be wasted. Paragraph chunks: ~1.28M after dedupe (was ~1.45M) |
| 2026-10 | Duplicate judgments are removed across year files (first year wins), not just inside one file; the 2026-10-15 GPU run (cards 43,546, chunks in progress) was started before this fix, so retrieval must drop repeated case ids when it loads the index | The first dedupe only compared records inside one year file and removed nothing: the 5,180 repeats are spread across year files. Cards and chunks are identical copies, so the only costs are about 12% extra embedding time and repeated ids |
| 2026-10 | Judgment retrieval stage 2 (backend/rag/judgments.py): top 12 cases by card similarity, then the best 2 paragraphs of each by chunk similarity; paragraph score = paragraph sim + 0.25 x card sim + 0.02 domain boost; refusal on the paragraph similarity | Brute force over all 1.41M paragraphs needs the 2.7 GB of vectors in RAM; this reads only ~12 cases' vectors from a memory map, so it fits free hosting. The 0.25 weight, the 12 cases and the refusal threshold (0.60) are PROVISIONAL guesses: no judgment test questions exist yet, so they must be tuned against cards-only and full-brute-force before the demo |
| 2026-10 | Judgment citation string = case name ("versus" shown as "v.") + SCR citation (or neutral citation if none) + court + year + "from para N" | Every part is metadata or the paragraph number printed in the judgment. "from para N" because a chunk can run on into later paragraphs; chunks that start mid-paragraph carry no number |
| 2026-10 | Retrieval reads a small sidecar (corpus/judgments_index/chunk_index, tools/build_judgment_offsets.py) with byte offsets and per-case row ranges, and drops repeated cases at load time (first year wins) | The GPU run predates the dedupe fix (cards 43,546, chunks 1,413,250 include ~5,000 repeated cases). Fixing it in the loader costs nothing and avoids re-embedding |
| 2026-10 | verify_citations accepts ids containing # and _ (sc-2001_1_1_9#12) | Judgment paragraph ids did not match the old pattern, so an id the model wrote would have been left in the answer unchecked. Found by the new test |
| 2026-10 | Domain tags are split on whitespace as well as commas | judgment_domains.csv writes multi-domain cases as "family property"; the first card run kept that as one string. The loader splits it; the scripts are fixed for any future run |
| 2026-10 | Judgment retrieval defaults: 50 cases to stage 2, card weight 0.5 (was 12 and 0.25) | First real-data run, 41 DRAFT questions, Gemini rewrite on: right case in the top 5 hits .69 with (50, .5) vs .57 with (12, .25). A full scan of all 1.41M paragraphs with no cards scores only .63, so the case cards add value and the plan to search every paragraph directly is not better. Small sample and strict labels (one gold case per question, but several real answers exist): treat as provisional |
| 2026-10 | Gemini query rewrite is used for judgments too (separate prompt, tools/eval_judgments.py --rewrite), but only to RANK; refusal looks at the similarity of the question as the person asked it | The rewrite lifted stage-1 recall (top 5 .46 -> .57, top 50 .71 -> .77) and fixed the Hindi land-title question. But it also dresses off-topic questions in legal words ("best recipe for chicken biryani" -> "maintainable writ petition civil procedure court jurisdiction"): with the better-of-both score, only 50% of traps were refused at 0.60 instead of 100%. Hits therefore carry both `similarity` (ranking) and `similarity_query` (refusal) |
| 2026-10 | Judgment test set: gold = one landmark case per question, 41 DRAFT questions | landmark_matches.csv maps D.K. Basu and Bachan Singh to short reports (S_1997_3_219_223 and 1980_1_645_649); the full judgments are S_1996_10_284_320 and 1983_1_145_371. Reading the misses, about 8 of 13 returned other correct cases (e.g. Mohan v Tamil Nadu and Santosh Bariyar for rarest-of-rare; Laureate Buildwell for builder delay) so the strict score understates quality; lawyers should list all acceptable cases per question |
| 2026-10 | Judgments wired into pipeline.answer: statutes (5) + up to 3 judgment paragraphs go to Gemini; each source family must clear its own refusal threshold, refuse only if neither does | Statutes keep their language-specific threshold; judgments use `similarity_query` >= 0.60 (question as asked, not the rewrite). Judgment rewrite is a separate Gemini call (3 calls per question: 2 rewrites + answer; CHAMBERS_REWRITE=0 or CHAMBERS_JUDGMENTS=0 turns parts off). Prompt gets a rule 8 only when judgment paragraphs are present: say what the court held, never present it as statute text. Citations still come from metadata via verify_citations |
| 2026-10 | Answer step: thinking budget 0 (env GEMINI_THINKING_BUDGET, -1 = model default), request timeout 45 s, output cap 4096 tokens | First end-to-end runs on the Mac: retrieval 8 s, rewrites 2 s, but generation 87-156 s (a 60 s timeout plus retry). Answers only restate retrieved text, so thinking adds latency not quality. A 400 from a model that rejects the setting retries without it. tools/time_gemini.py compares models |
| 2026-10 | Answer model: gemini-flash-lite-latest first, gemini-flash-latest as fallback; retry waits 1 s and 3 s; thinking setting off unless GEMINI_THINKING_BUDGET is set | tools/time_gemini.py on the Mac: flash-latest answered 503 (high demand, 115 s) and 429 (free-tier quota); flash-lite answered in 3.5 s and rejects thinkingBudget with a 400. Answers from lite were as good in the manual checks (rarest-of-rare, divorce grounds). Revisit with a billing-enabled key (set GEMINI_MODEL=gemini-flash-latest to compare) |
| 2026-10 | Answers carry numbered citation markers ([1], [2, 3]) and `citations` is the list in marker order; same citation text = same number | The first end-to-end runs repeated the full case name after almost every sentence (unreadable, and unusable for voice). verify_citations(numbered=True); markers must be stripped before text-to-speech (docs/CONTRACTS.md). Citation text itself still comes only from chunk metadata |
